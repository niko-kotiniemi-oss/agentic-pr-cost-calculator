# B-001: Patterns and anti-patterns

- **Status:** Planned
- **Last changed:** 2026-11-13
- **Brief:** A page that lists each recognised pattern that the design follows and each anti-pattern that it avoids or knowingly accepts. It comes from an assessment by reviewers of their own, and each anti-pattern found is fixed before the build.
- **Rests on:** DR-166
- **Issue:** none
- **Pull requests:** 28

## Problem

The design is large and has no code yet. Without a written assessment, a pattern that it follows by choice and an anti-pattern that it has drifted into look alike, and agents that work here have no short page that tells them which is which.

## What done looks like

A page lists each pattern that the tool follows, with its source, where it applies and the record that chose it, and each anti-pattern that it avoids or knowingly accepts, with the reason. The page describes and never steers, as the glossary does (DR-166). Each anti-pattern that the assessment finds has its fix in the item on the tool's requirements (B-007), or a record that accepts it with its reason.

## Postponed points

None.
