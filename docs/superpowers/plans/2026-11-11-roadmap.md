# Roadmap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build task 1.26 of `add-pr-cost-calculator`: the roadmap, `docs/roadmap.md`, its link from the README, a section on known limitations and the roadmap on each feature page, and `tests/test_roadmap.py`, which holds R206 to R210.

**Architecture:** One test module reads the roadmap, the README, the feature pages, the requirements register, the decision records, the threat model and every change's `tasks.md` and `design.md`, active or archived, and returns problems, each naming the file and what is wrong. The repository's own pages must give none, and each check is shown to fail on a synthetic tree, made a git repository so that tracked files can be read, into which the defect it exists for is planted.

**Tech Stack:** Python 3.11 standard library, pytest, git.

**Spec:** `openspec/changes/add-pr-cost-calculator/specs/project-standards/spec.md`, requirements R206 to R210 with their scenarios; task 1.26; design decisions 12 and 14; the roadmap's records, DR-220, DR-222 and DR-223, and those that DR-225 to DR-228 replaced; the threats T159 to T165.

## Global Constraints

- The test uses the standard library and git alone, and never the network: no test reads an issue (T161).
- Every check is seen to fail for the expected reason before the page exists, and a test plants each defect that task 1.26 lists.
- The roadmap names issues and pull requests by number alone (DR-228); it and each feature page's new section give no fenced or indented code, no image and no `@`, and link only their own headings and tracked files of this repository (R209).
- The roadmap, and each feature page's new section, hold printable ASCII and line feeds only, and nowhere, inline code included, a `<`, a `&`, a backslash, a `]:` or a link with a title (R210).
- The roadmap and the sections describe; they never tell a reader or an agent what to do (DR-227).

## The grammar the test reads

- Sections: the roadmap's `## ` headings are exactly Now, Next, Later, Known limitations and Known bugs, in that order.
- An item: a line under Next or Later that starts with `- `, with the indented lines that follow it. It opens with `**Planned.**` or `**Open to feedback and contributions.**`.
- What an item names: `R` and digits, `DR-` and three digits, `T` and digits, and a task as `task 1.26 of `add-pr-cost-calculator``, the change's name given as code.
- Later's opening: the paragraph between its heading and its first item holds the sentence that `LATER_OPENING` gives.
- A risk: in a design's `## Risks / Trade-offs`, a line that opens with `- [title]` and the arrow U+2192. A listed risk: in Known limitations, or in a feature page's `## Known limitations and the roadmap`, a line `- **title**: ...`.
- A feature page named for a spec: a page in `docs/features/` whose name, less `.md`, is the name of a spec folder of `openspec/specs/` or of a change.
- An `owner/repo`: any run of word characters, dots and hyphens on both sides of a slash, outside a link's target, which must then be a tracked path from the repository's root.
