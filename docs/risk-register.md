# Risk register

`scripts/risk_register.py` writes this page from the threat model, [`docs/threat-model.md`](threat-model.md), the specs and the register of requirements. It is not edited by hand, and CI fails when it differs from what the script writes (R245, DR-256).

Each threat has two ratings, each an impact and a likelihood from 1 to 3 as the threat model's method defines them, whose product is its risk. The raw rating takes the threat's answer as not built (R244, DR-254). The rating with the answer in place takes the answer as built as specified, before any code is built, until the review of what was built rates it again (DR-112).

Each risk takes the band that the overall risk severity of OWASP's Risk Rating Methodology gives its score (R247, DR-253). Each threat whose risk with its answer in place is high or critical carries a further answer or, for a high one only, the owner's acceptance (R249, DR-255).

## High and critical risks

Each threat whose risk with its answer in place is high or critical, highest first, with its further answer or its acceptance (R249).

- [T2](threat-model.md#t2-work-in-another-repository-is-published-here): Work in another repository is published here. 6 high, raw 9 critical. Acceptance: DR-257: the owner accepts it, since the owner chose to tell a call's repository by its working directory alone, and only the person working can avoid it.
- [T32](threat-model.md#t32-private-data-enters-this-public-repository): Private data enters this public repository. 6 high, raw 9 critical. Acceptance: DR-257: the owner accepts it, since a private name that no pattern knows is seen only by its author or by the owner reading the diff.
- [T33](threat-model.md#t33-text-in-the-repository-steers-an-agent): Text in the repository steers an agent. 6 high, raw 9 critical. Acceptance: DR-257: the owner accepts it, since no check tells text that instructs from text that describes, so it rests on agents following `CLAUDE.md` and on the owner's merge.
- [T34](threat-model.md#t34-a-session-on-a-contributors-branch-runs-that-branchs-instructions): A session on a contributor's branch runs that branch's instructions. 6 high, raw 9 critical. Acceptance: DR-257: the owner accepts it, since the branch controls what a session on it loads, so it rests on no session starting on an outside contributor's branch.
- [T61](threat-model.md#t61-a-bug-report-carries-private-data): A bug report carries private data. 6 high, raw 9 critical. Acceptance: DR-257: the owner accepts it, since an issue is public once it is posted, so it rests on the reporter heeding the form's warning.
- [T65](threat-model.md#t65-private-references-reach-pull-request-text): Private references reach pull request text. 6 high, raw 9 critical. Further answer: A PreToolUse hook that `.claude/settings.json` registers checks the text of each tool call that opens or edits a pull request, an issue or a comment against the same private patterns and name hashes as R33, and blocks the call before the text is posted, which a test holds with synthetic tool input with and without a session link; B-007
- [T132](threat-model.md#t132-a-change-to-the-marketplace-reaches-sessions-with-nothing-to-accept): A change to the marketplace reaches sessions with nothing to accept. 6 high, raw 9 critical. Further answer: A pull request that changes the root marketplace file or the plugin folder is also checked by the marketplace's checks as its base commit holds them, run over the pull request's files read as data, by a means that runs none of its code and holds no secret and no write token, so that one that weakens a check and moves the folder together fails the base's check; B-007, whose design threat-models that means
- [T232](threat-model.md#t232-another-repositorys-context-files-loaded-in-the-same-session-steer-work-here): Another repository's context files, loaded in the same session, steer work here. 6 high, raw 9 critical. Acceptance: DR-266: the owner accepts it, since it rests on a choice that the owner made, to keep this repository's threads until task 7.1 in a project that holds another repository too, so that until then it rests on agents following the root.
- [T7](threat-model.md#t7-one-call-is-counted-more-than-once-or-from-a-partial-line): One call is counted more than once, or from a partial line. 6 high, raw 6 high. Acceptance: DR-257: the owner accepts it, since in one shape of subagent transcript Claude Code writes no usage at a call's end, and the comment says that the cost is a lower bound.
- [T8](threat-model.md#t8-usage-never-reaches-the-pull-request): Usage never reaches the pull request. 6 high, raw 6 high. Further answer: Before a git push that the hook's condition matches, a run that holds calls recorded on the checked-out branch that no commit carries makes a commit that holds only the ledger file, so that the push carries them, as the record that replaces DR-010 weighs, with what a commit that the step makes on its own costs the person; B-007
- [T16](threat-model.md#t16-a-ledger-file-is-edited-by-hand-to-change-the-cost): A ledger file is edited by hand to change the cost. 6 high, raw 6 high. Acceptance: DR-257: the owner accepts it, since nothing that the report trusts signs the ledger, so only a reviewer of the diff sees an edited count, and the figure is an estimate, not a bill.
- [T62](threat-model.md#t62-a-code-owner-rule-invites-a-bypass-that-agent-sessions-share): A code-owner rule invites a bypass that agent sessions share. 6 high, raw 6 high. Acceptance: DR-257: the owner accepts it, since it rests on two settings that only the owner keeps, code-owner review off and no bypass actor on the default branch's ruleset.
- [T128](threat-model.md#t128-calls-made-from-a-folder-that-holds-the-repository-are-left-out-so-a-threads-figure-is-far-too-low): Calls made from a folder that holds the repository are left out, so a thread's figure is far too low. 6 high, raw 6 high. Acceptance: DR-257: the owner accepts it, since the owner chose to leave out and flag with no count the calls made from a folder that holds the repository.
- [T137](threat-model.md#t137-one-pull-request-changes-the-marketplace-together-with-the-check-the-build-or-the-workflow-that-compares-it): One pull request changes the marketplace together with the check, the build or the workflow that compares it. 6 high, raw 6 high. Further answer: The check that fails a pull request that changes the marketplace together with anything else runs as the base commit holds it, over the pull request's changed paths read as data, by a means that runs none of its code and holds no secret and no write token, which a test of the workflow holds; B-007, whose design threat-models that means
